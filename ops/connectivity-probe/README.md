# Connectivity Probe — آزمون اتصال زیرساخت (مرحلهٔ ۲B)

بستهٔ **مستقل و قابل استفادهٔ دوباره** برای سنجش اینکه یک سرور (مثلاً VPS ایرانی) از شبکه‌های واقعی کاربران چقدر قابل دسترس است.
**به فروشگاه، بک‌اند، پایگاه داده یا هر داده/رمز واقعی وصل نیست.** فقط nginx + یک صفحهٔ HTML ساده.
هیچ چیزی را مستقر نمی‌کند، خرید نمی‌کند، و وابستگی پولی ندارد.

## چه چیزی را می‌سنجد
یک صفحهٔ فارسی (RTL، موبایل‌محور) این مراحل را از مرورگر کاربر اجرا و نتیجه را روشن نشان می‌دهد:
صفحه و HTTPS · تصویر ~۳۰۰KB · فهرست ~۱۰۰KB از دامنهٔ فروشگاه · API روی **دامنهٔ دیگر (CORS)** · فهرست از API · **کوکی نشست بین دو زیردامنه** · سبد (POST) · سفارش حجیم ۶۰۰KB (POST) · ۲۰ درخواست پیاپی · **رفت‌وبرگشت «درگاه»** (تغییر مسیر به دامنهٔ سوم و بازگشت) · نوع آدرس IPv4/IPv6 (نه خود آدرس).
خروجی JSON اختیاری (ذخیره، کپی یا ارسال به سرور آزمون) و `scripts/summarize.mjs` برای حکم Go/No-Go.

## ساختار
```
nginx/probe.conf.template   پیکربندی (پاسخ‌های ثابت؛ بدون proxy_pass؛ محدودیت نرخ/اندازه؛ لاگ بدون IP خام)
scripts/render.sh           ساخت پیکربندی از الگو       scripts/self-check.sh   بررسی سرور در حال اجرا
automation/                 استقرار/پاکسازی خودکار (API ساختگی برای آزمون)
scripts/summarize.mjs       خلاصه و حکم                 scripts/make-assets.mjs ساخت تصویر/فهرست نمونهٔ قطعی
web/                        صفحهٔ آزمون (بدون وابستگی خارجی)
criteria.json               آستانه‌های Go/No-Go          templates/results-template.csv  برگهٔ دستی
test/                       آزمون‌های خودکار (nginx واقعی، مرورگر واقعی)
docs/                       مستندات فارسی (فهرست پایین)
```

## اجرای آزمون‌ها
```bash
node --test --test-concurrency=1 "test/*.test.mjs"
```
نیاز: nginx، openssl، curl؛ و برای آزمون مرورگر `playwright` + Chromium (آزمون‌های بدون ابزار لازم، رد می‌شوند و علت را نشان می‌دهند). CI: `.github/workflows/connectivity-probe.yml`.

## محدودیت‌ها (صادقانه)
- ارسال نتیجه به سرور با GET و مقدار base64url است (nginx بدنهٔ POST را بدون برنامهٔ پشتیبان لاگ نمی‌کند)؛ نتیجهٔ خیلی بزرگ خلاصه می‌شود.
- محدودیت نرخ و اندازه برای آزمون ساده است، نه محافظت در برابر حملهٔ جدی؛ سرور آزمایشی را فقط موقت و محدود نگه دارید.
- «موفق» فقط برای همان شبکه و زمان است؛ قطع واقعی بین‌الملل، درگاه بانکی و پیامک را نمی‌سنجد.
