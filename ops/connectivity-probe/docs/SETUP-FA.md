# راه‌اندازی بستهٔ آزمون اتصال (Connectivity Probe)

> این بسته **مستقل** از فروشگاه «جریان ما» است: کدی از فروشگاه یا بک‌اند نمی‌خواهد، به پایگاه داده وصل نمی‌شود و هیچ اطلاعات واقعی (مشتری، سفارش، پرداخت، رمز) ندارد.
> فقط **nginx** با چند پاسخ ثابت و یک صفحهٔ HTML ساده است. هیچ سرویس یا وابستگی پولی ندارد.

## ۱. چه چیزی لازم است
- یک سرور مجازی (VPS) آزمایشی با **Ubuntu 22.04/24.04** و دسترسی root، و IPv4 عمومی (IPv6 اختیاری).
- یک **دامنه** که بتوانید رکوردهای DNS آن را بسازید (سه نام زیر یک دامنه): `probe.D`، `probe-api.D`، `probe-pay.D` (به‌جای `D` دامنهٔ خودتان، مثلاً `example.ir`).
  این سه نام لازم‌اند چون آزمون «درخواست بین دو دامنه (CORS)» و «کوکی بین دو زیردامنه» و «تغییر مسیر به درگاه» را شبیه‌سازی می‌کنند.
- **گواهی HTTPS معتبر** برای هر سه نام (بخش ۴). آزمون با گواهی نامعتبر یا خودامضا **بی‌معنی** است، چون مرورگر گوشی‌ها آن را رد می‌کند.
- هزینه: فقط خودِ سرور آزمایشی (و دامنه). این بسته هیچ هزینه‌ای اضافه نمی‌کند. **خرید سرور یا دامنه را شما انجام می‌دهید؛ این بسته چیزی نمی‌خرد و چیزی نصب نمی‌کند مگر دستوری که خودتان اجرا کنید.**

## ۲. نصب (روی سرور آزمایشی، به‌عنوان root)
```bash
apt-get update && apt-get install -y nginx openssl
# بستهٔ ops/connectivity-probe را روی سرور کپی کنید (مثلاً با scp یا git clone) به /opt/jm-probe
mkdir -p /var/www/jm-probe/acme
cp -r /opt/jm-probe/web /var/www/jm-probe/web
```
اگر IPv6 دارید در مرحلهٔ بعد `--ipv6` را هم بدهید.

## ۳. تولید پیکربندی nginx
ابتدا گواهی را بگیرید (بخش ۴)؛ سپس:
```bash
bash /opt/jm-probe/scripts/render.sh --domain example.ir \
  --cert-dir /etc/letsencrypt/live/probe.example.ir \
  --web-root /var/www/jm-probe/web --acme-root /var/www/jm-probe/acme \
  --log-dir /var/log/nginx --out /etc/nginx/conf.d/jm-probe.conf
rm -f /etc/nginx/sites-enabled/default     # صفحهٔ پیش‌فرض nginx را بردارید
nginx -t && systemctl reload nginx
```
`render.sh` فقط فایل پیکربندی می‌سازد و جای دیگری را تغییر نمی‌دهد. ورودی‌ها را بررسی می‌کند (دامنه و مسیرها).
اگر nginx شما `limit_req` یا `ssl_reject_handshake` را نمی‌شناسد، نسخه‌اش قدیمی است: nginx ≥ ۱٫۱۹٫۴ لازم است.

## ۴. HTTPS معتبر
روش اول (گواهی عمومی رایگان Let's Encrypt؛ **نیاز به دسترسی سرور به اینترنت جهانی دارد و این خودش یک فرض آزمون‌نشده برای سرورهای داخل ایران است**):
```bash
apt-get install -y certbot
# گام ۱: فقط پورت ۸۰ با پیکربندی موقت (یا --standalone) برای اثبات مالکیت دامنه
certbot certonly --standalone -d probe.example.ir -d probe-api.example.ir -d probe-pay.example.ir
```
یک گواهی با هر سه نام ساخته می‌شود؛ پوشهٔ `--cert-dir` همان `/etc/letsencrypt/live/probe.example.ir` است.
تمدید: `certbot renew` (آزمون ۲۴–۷۲ ساعت یا ۷ روزه معمولاً به تمدید نمی‌رسد؛ گواهی ۹۰ روزه است).

روش‌های دیگر اگر سرور نمی‌تواند به Let's Encrypt برسد:
- گواهی از **مرجع صدور ایرانی** یا گواهی‌ای که ارائه‌دهنده می‌فروشد/می‌دهد (فایل‌های `fullchain.pem` و `privkey.pem` را در یک پوشه بگذارید).
- اگر ارائه‌دهنده CDN/پروکسی خودش را دارد (مثل ابر آروان)، می‌توان HTTPS را در لبهٔ CDN تمام کرد؛ **اما آن‌وقت آزمون، مسیر CDN را می‌سنجد نه خودِ سرور.** این حالت را در برگهٔ نتایج حتماً علامت بزنید (`notes`) و جدا ارزیابی کنید.

> هر ارائه‌دهنده‌ای که نام موقت با HTTPS معتبر بدهد، کار را ساده می‌کند؛ ولی چنین امکانی **برای هیچ ارائه‌دهنده‌ای تأیید نشده** (فایل `ARVANCLOUD-FA.md`). فرض نکنید.

## ۵. بررسی خودکار از بیرون
از هر رایانه‌ای که `curl` دارد (ترجیحاً خارج از خودِ سرور):
```bash
bash scripts/self-check.sh --domain example.ir
```
همه باید `PASS` شوند و آخرش `ALL CHECKS PASSED` بیاید. این بررسی گواهی معتبر، CORS، کوکی، تغییر مسیر پرداخت، محدودیت اندازهٔ بدنه و رد TLS قدیمی را می‌سنجد.

## ۶. چه چیزهایی در سرور ثبت می‌شود
- لاگ دسترسی: زمان، **آدرس ماسک‌شده** (IPv4 آخرین بایت صفر؛ IPv6 فقط سه گروه اول)، نام میزبان، متد و مسیر **بدون query**، کد، زمان، اندازه، نسخهٔ TLS.
- لاگ نتایج (اختیاری): زمان + نتیجهٔ ارسال‌شده توسط صفحه (بدون آدرس).
- جزئیات و محدودیت‌های اجتناب‌ناپذیر: `PRIVACY-FA.md`.

## ۷. جمع‌کردن آزمون
پس از پایان: `rm /etc/nginx/conf.d/jm-probe.conf && systemctl reload nginx`، سرور را حذف یا خاموش کنید، رکوردهای DNS را پاک کنید، و لاگ‌ها را پاک کنید (`/var/log/nginx/jm-probe-*.log`).

## ۸. اجرای آزمون‌های خودکار (برای توسعه‌دهنده)
```bash
cd ops/connectivity-probe && node --test --test-concurrency=1 "test/*.test.mjs"
```
نیاز: nginx، openssl، curl؛ برای آزمون مرورگر: `playwright` (نصب‌شده در ریشهٔ مخزن) و Chromium.
