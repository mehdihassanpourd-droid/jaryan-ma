# معیارهای Go / No-Go

> مقادیر زیر **پیشنهاد** هستند (نه حقیقت اندازه‌گیری‌شده). در `criteria.json` هستند و مالک می‌تواند عوض کند؛ `summarize.mjs` همان فایل را می‌خواند.

## تعاریف
- **اجرای مستقیم**: آزمون با VPN خاموش، با اپراتور/اینترنت داخل ایران.
- **قبولی کامل**: حکم `pass`؛ یعنی مرور (تصویر/فهرست)، API بین‌دامنه‌ای، کوکی، سبد و سفارش حجیم و رفت‌وبرگشت درگاه همه موفق بودند.

## شرط‌های لازم برای GO
| # | شرط | آستانه |
|---|---|---|
| ۱ | تعداد اجرای مستقیم | ≥ ۳۰ |
| ۲ | تعداد شبکه‌های متفاوت (هر کدام ≥ ۳ اجرا) | ≥ ۳، و دست‌کم یک اپراتور همراه |
| ۳ | درصد قبولی کامل در اجرای مستقیم | ≥ ۹۵٪ |
| ۴ | رفت‌وبرگشت درگاه شبیه‌سازی‌شده | ≥ ۹۵٪ |
| ۵ | زمان ثبت سفارش حجیم (۶۰۰ کیلوبایت)، صدک ۹۵ | ≤ ۸ ثانیه |
| ۶ | HTTPS با گواهی معتبر و بدون هشدار در همهٔ اجراها | بدون استثنا (هر هشدار گواهی = شکست) |
| ۷ | `self-check.sh` بدون `--insecure` | همه `PASS` |

## شرط‌های تکمیلی (برای «GO» کامل، وگرنه «GO با موارد باز»)
- روزهای متفاوت ≥ ۷ (آزمون هفت‌روزه).
- با VPN روشن (داخل ایران) قبولی کامل ≥ ۸۰٪. **هیچ تضمینی نداریم که VPN های کاربران به IP ایرانی برسند؛ این شرط باید با داده ثابت شود.**
- از داخل مرورگر اینستاگرام: نتایج مجزا (در `notes`) و بدون شکست نظام‌مند.

## احکام
| حکم | یعنی |
|---|---|
| **GO** | همهٔ شرط‌ها برقرارند. می‌توان خرید ارائه‌دهنده را برای مرحلهٔ بعد (تأیید مالک) مطرح کرد. |
| **GO با موارد باز** | شرط‌های لازم برقرار، ولی هفت‌روزه یا VPN-روشن کامل نیست؛ ادامهٔ آزمون یا پذیرفتن ریسک با تصمیم مالک. |
| **هنوز نه** | داده کافی است ولی یک شرط لازم رد شد (مثلاً درگاه یا یک اپراتور). علت را رفع و تکرار کنید. |
| **NO-GO** | قبولی کامل مستقیم زیر ۸۰٪: ارائه‌دهنده/مسیر رد شود. |
| **داده ناکافی** | آزمونگر/اپراتور/اجرای بیشتر لازم است. |

## چیزهایی که این آزمون **اثبات نمی‌کند**
- رفتار در زمان قطع واقعی اینترنت بین‌الملل.
- دسترسی سرور به درگاه پرداخت، پیامک یا ارسال (این‌ها جداگانه).
- بار واقعی (فقط محدودیت نرخ ساده دارد).
- یک «GO» هیچ‌گاه به‌تنهایی خرید یا استقرار را مجاز نمی‌کند؛ این تصمیم با مالک است.
