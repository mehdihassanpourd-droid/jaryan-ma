# راه‌اندازی یک‌باره Google Search Console برای پایش خودکار سئو

> این راهنما فقط یک بار لازم است و **هیچ هزینه‌ای ندارد** (Search Console و Google Cloud برای این کار رایگان‌اند). هیچ کلید، گذرواژه یا فایلی را در گفتگو، کد یا issue نفرستید؛ فقط داخل «Secrets» مخزن گیت‌هاب قرار می‌گیرد.
>
> تا وقتی این مراحل انجام نشود، سیستم کار می‌کند ولی **داده‌ای از گوگل ندارد**: بررسی فنی سایت اجرا می‌شود و گزارش‌ها صریح می‌گویند «داده‌ای از Search Console ذخیره نشده است». هیچ ترافیک یا رتبهٔ ساختگی ساخته نمی‌شود.

## پیش‌نیاز
سایت باید روی یک دامنهٔ واقعی منتشر شده و در Search Console ثبت و تأیید (verify) شده باشد. (Search Console داده را فقط برای سایت‌های تأییدشده می‌دهد و برای سایت‌های نو چند روز طول می‌کشد تا داده بیاید.)

## مرحله ۱ – ساخت حساب سرویس (Service Account)
1. به <https://console.cloud.google.com> بروید و یک پروژهٔ تازه بسازید (مثلاً `jaryan-seo`).
2. از منوی «APIs & Services ← Library»، **Google Search Console API** را پیدا کنید و «Enable» بزنید.
3. «APIs & Services ← Credentials ← Create credentials ← Service account» را بزنید، یک نام بدهید (مثلاً `seo-monitor`) و بدون نقش خاصی بسازید.
4. وارد حساب سرویس شوید ← تب «Keys» ← «Add key ← Create new key ← JSON». یک فایل JSON دانلود می‌شود. **این فایل مثل گذرواژه است.**
5. آدرس ایمیل حساب سرویس (چیزی شبیه `seo-monitor@jaryan-seo.iam.gserviceaccount.com`) را کپی کنید.

## مرحله ۲ – دادن دسترسی فقط‌خواندنی در Search Console
1. در <https://search.google.com/search-console> وارد ملک (property) سایتتان شوید.
2. «Settings ← Users and permissions ← Add user».
3. ایمیل حساب سرویس را بنویسید و سطح دسترسی را **Restricted** (فقط خواندن) بگذارید.

## مرحله ۳ – ثبت در گیت‌هاب
مخزن را باز کنید: «Settings ← Secrets and variables ← Actions».

**Secret** (تب Secrets):
| نام | مقدار |
|---|---|
| `GSC_SERVICE_ACCOUNT_JSON` | کل محتوای فایل JSON مرحلهٔ ۱ (کپی/پیست) |

**Variables** (تب Variables):
| نام | مقدار | توضیح |
|---|---|---|
| `GSC_SITE_URL` | `sc-domain:example.ir` یا `https://example.ir/` | دقیقاً همان‌طور که ملک در Search Console ثبت شده (ملک دامنه: `sc-domain:`؛ ملک پیشوند آدرس: با `https://` و `/` پایانی) |
| `SITE_URL` | `https://example.ir` | برای بررسی فنی سایت زنده |
| `CATALOG_SNAPSHOT_URL` | آدرس عمومی فایل‌های کاتالوگ | برای ساخت پیشنهادها و تشخیص تغییر کاتالوگ |
| `SEO_ALLOW_INDEXING` | `true` | **فقط بعد از آمادگی کامل برای راه‌اندازی عمومی** (همان کلید باز شدن سایت برای گوگل) |
| `SEO_REBUILD_ON_CATALOG_CHANGE` | `true` | اختیاری: با تغییر کاتالوگ، سایت دوباره ساخته شود تا نقشهٔ سایت و صفحه‌های محصول به‌روز بمانند |

## مرحله ۴ – اجازهٔ ساخت درخواست ادغام (PR) توسط اکشن‌ها
«Settings ← Actions ← General ← Workflow permissions» را باز کنید و گزینهٔ **Allow GitHub Actions to create and approve pull requests** را روشن کنید. (سیستم فقط PR باز می‌کند؛ **هیچ‌وقت چیزی را ادغام نمی‌کند**.)
نکته: PR هایی که با توکن خود اکشن‌ها ساخته می‌شوند به‌طور خودکار بررسی‌های CI را اجرا نمی‌کنند؛ قبل از ادغام، در صفحهٔ PR دکمهٔ «Update branch» را بزنید یا بررسی‌ها را دستی اجرا کنید.

## مرحله ۵ – آزمایش
از تب Actions ← «SEO monitor» ← «Run workflow» (گزینهٔ `report` را `weekly` بگذارید). بعد از اجرا:
* داده‌ها و گزارش‌ها در شاخهٔ `seo-data` (فقط داده، بدون کد) ذخیره می‌شوند.
* خلاصهٔ گزارش در صفحهٔ اجرا (Summary) دیده می‌شود.
* اگر خطای `gsc_forbidden` دیدید، یعنی ایمیل حساب سرویس در Search Console اضافه نشده است (مرحلهٔ ۲). اگر `gsc_not_found` دیدید، مقدار `GSC_SITE_URL` با ملک ثبت‌شده یکی نیست.

## بعد از راه‌اندازی چه اتفاقی می‌افتد
* **روزانه:** دریافت داده (۵ روز اخیر دوباره بررسی می‌شود چون گوگل داده را با تأخیر نهایی می‌کند)، بررسی فنی سایت زنده، ذخیرهٔ تاریخچه.
* **دوشنبه‌ها:** گزارش هفتگی (در Summary و شاخهٔ `seo-data`) و در صورت وجود صفحهٔ «نمایش زیاد و کلیک کم»، یک PR با پیشنهاد عنوان/توضیح که فقط از اطلاعات واقعی کاتالوگ ساخته شده.
* **اول هر ماه:** گزارش ماهانه (۲۸ روز).
* **بعد از ادغام یک پیشنهاد توسط شما:** نتیجه ۱۴ و ۲۸ روز بعد در گزارش‌ها اندازه‌گیری می‌شود.
